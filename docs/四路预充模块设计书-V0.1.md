# 四路预充模块设计书

**V0.1 · 评审稿 · 2026-11-19**

本设计以已确认的硬件流程、板级接线和[主控板与预充板通信协议 V0.1](主控板与预充板通信协议-V0.1.md)为输入，独立定义预充模块。文中的“拟定”是本设计提出的实现选择，“待定”需要整机或硬件评审确认。

## 1. 职责与边界

| 所属 | 职责 |
|---|---|
| 主板 | 管理整机联锁和旁路接触器，发起启动、停止和心跳，确认旁路实际吸合后应答预充完成，处理运行故障 |
| 预充任务 | 同步组织四路检测，管理四路继电器和 PB13，判断电压及漏电，产生业务结果，维护运行灯 |
| 485 任务 | 回应主板心跳，转交控制指令，发送状态与漏电上报，管理应答匹配及重发 |
| BSP | 提供 GPIO、成对 ADC 快照、CAN 控制器及串口能力，维护板级配置 |

采用**一个预充任务、一个 485 任务**。四路共享同一个操作流程和接管结果，通道差异用位图和采样数据表达。独立 CAN 任务适合后续有多个 CAN 业务、需要独立调度的场景。本项目的 MP10 收发、诊断判定及采样屏蔽都由预充任务协调，放在同一任务中可以保持时间和状态归属清楚。任务各自注册看门狗，周期工作完成后喂狗。

## 2. 预充状态机

| 状态 | 进入动作或行为 | 转移 |
|---|---|---|
| 空闲 | 四路预充输出断开，PB13 断开 | 接受启动后进入采样稳定 |
| 采样稳定 | 闭合 PB13，立即暂停漏电判定，等待 ADC 稳定 | 到期进入输入观察 |
| 输入观察 | 用连续完整采样记录每路输入侧最小值、最大值和有效采样覆盖 | 0.5 s 后四路均合格，闭合四路继电器，进入预充等待。有不合格通道则撤销并上报 |
| 预充等待 | 从四路吸合指令执行成功后计时 | 到暂定 2T 时只判断一次，使用一轮有效前后电压快照 |
| 等待接管 | 电压通过后断开 PB13，发布预充完成，四路继电器保持吸合 | 有效接管确认后释放四路并进入运行监测。联调超时则撤销并上报，时间暂定 3 s |
| 运行监测 | 四路预充继电器和 PB13 均断开，主板旁路负责运行，持续判断漏电 | 停止后回空闲。漏电等事件按约定上报 |
| 故障 | 尝试将四路输出和 PB13 全部撤销，保存首个业务故障及输出撤销错误 | 输出未能撤销时拒绝再次启动。其余故障的恢复条件按评审结果配置 |

停止请求在所有活动阶段优先处理，结束当前预充或运行监测，撤销输出并使未发送的完成上报失效。重复停止可以应答受理。活动阶段重复启动返回忙。启动应答只表示请求受理，最终结果由状态上报表达。

四路按同一批操作执行。一旦发现任一路需要中止，尝试撤销全部四路和 PB13，即使某一路释放失败也继续释放其余输出。释放成功代表软件操作成功，实际触点状态需要物理反馈确认。预充板以主板匹配的应答作为主板确认旁路吸合的依据。主板只能在旁路实际吸合后发送该应答。

## 3. 采样与电压判定

- PA0/PA1、PA2/PA3、PA4/PA5、PA6/PA7 分别是四路输入侧和电阻后回读。双 ADC 并行获取每对信号，四对之间仍有扫描时差。BSP 每次交付带采样时间及有效位图的一轮快照。控制层只使用完整、新鲜且属于当前阶段的样本。
- 电压换算使用硬件给定的关系 `V_high = (1.5 V − V_adc) × 3441 / 2`。应用内部统一用有符号 mV。零点、增益、ADC 饱和范围和判据误差需实测标定。
- 输入观察阶段使用四路**输入侧**值。硬件流程给出 10% 波动界限，百分比的基准、等于界限的归属和最低有效采样覆盖需确认。窗口没有足够有效数据时，结果为采样故障。
- 暂按 `T = 700 ms`、`2T = 1.4 s`。检查点取到时后的第一份完整快照，允许的调度偏差和采样最大年龄需确认。硬件流程给出的通过条件是四路输入均大于 200 V，且各路前后绝对压差均小于 30 V。失败位图按实际不合格通道生成。
- 2T 是一次电压判定时刻。若整机要求在等待期间也能对指定异常立即撤销，需要补充可连续检测的异常项目和最大撤销时延。

## 4. MP10 与漏电监测

| 通道 | 周期测量 ID | 自检请求 ID | 自检应答 ID |
|---|---|---|---|
| CH1 | `0x23D` | `0x46A` | `0x46B` |
| CH2 | `0x23E` | `0x47A` | `0x47B` |
| CH3 | `0x23F` | `0x48A` | `0x48B` |
| CH4 | `0x240` | `0x49A` | `0x49B` |

四台设备在装板前逐台配置上述扩展 ID。上电后，识别到每台设备的周期帧即将其列为可自检设备。按路发送 `44 03`，匹配对应应答 ID 上的 `51 44` 或 `7F 44`。每路上电尝试一次。发送失败或应答超时记录该路结果，调度继续处理其他已上线通道。迟到事件通过通道和当前请求状态隔离。底层发送未完成时，应用超时不能视为硬件已取消发送。

拟定每路只保存最新测量、接收时间和自检结果。在线状态由样本年龄判断。设备故障、未通过自检、帧已过期或处于恢复窗口时，其数据不可用于漏电判定。MP10 初始化失败及单路不可用应有可诊断结果，主板如何获知各类不可用、不可用时是否允许启动由整机评审确定。

漏电判定采用同一套监测逻辑覆盖等待接管和运行监测。PB13 闭合期间继续接收帧，清除或停止累积此次监测的持续超限计时。PB13 释放并稳定后，从释放窗口之后收到的有效新帧重新计时。样本失效或电流回到阈值内时结束本次连续超限计时。满足持续条件时，记录通道位图和该时点的电流并主动上报。阈值、持续时间、恢复滞回、持续超限重报及是否要求撤销输出均待定。

## 5. 两个任务如何交互

拟定采用动作接口加最小结果快照。485 任务提交启动、停止、接管确认，预充任务自行判断是否受理并执行。预充侧在短临界区内交换请求和结果，硬件 I/O 与串口收发在临界区外完成。任务之间无需消息队列。CAN 中断到预充任务沿用 RTOS 的有界事件交付机制。

| 接口语义 | 所有权 |
|---|---|
| 提交启动 | 预充侧受理判断，任务消费后初始化本轮 |
| 提交停止 | 预充侧消费停止请求并撤销输出，优先于待处理的启动和确认 |
| 提交接管确认 | 485 先匹配本次完成上报的线上序号，预充侧再核对当前是否等待接管及是否超时 |
| 读取待上报结果 | 预充侧冻结事件数据，485 侧取得副本并管理发帧和重发 |

完成事件和故障结果采用固定槽保存，避免下一轮周期采样覆盖尚未读取的事件。拟定完成通知与终止故障各保留一条，故障使尚未发送的旧完成通知失效。发生同类型事件积压时的覆盖或合并策略需在联调中冻结。485 持有线上上报序号，重复发送沿用原序号。正常业务无需让调用方传递内部阶段或截止时间。

RS485 沿用协议的三类交互。**主板定时发心跳，预充板返回空 Data 应答**。预充板用本地收到有效心跳的时间判断主板在线。启动和停止由主板发起。预充完成、故障及漏电由预充板主动上报，主板应答。主板心跳已有应答窗口，因此仍需协商半双工主动上报的发送窗口，确保完成上报和确认回传能在 3 s 联调预算内结束。

## 6. 数据归属、调度与调试

- 预充任务保存一份当前流程状态、阶段截止时间和四路观察数据。进入新阶段时更新截止时间，按本地单调时钟判断超时。是否能受理启动从当前阶段、待处理请求及故障锁定条件推导。
- MP10 子模块保存每通道最新采样和自检结果。LED 的翻转时刻及输出状态由预充任务持有。只读通道配置保存在常量表。
- 每轮先处理停止及到期的控制动作，再处理有上限的 CAN 事件和诊断工作，避免高频 CAN 流量推迟撤销输出。任务周期、每轮 CAN 配额和栈预算以实测为准。看门狗用于恢复异常任务，输出撤销时限由控制路径单独验证。
- 保留 Shell 对 PB3～PB6 的直接写入能力。拟定将这项能力用于受控调试，联调时核实手动输出对自动状态机和漏电判定的影响。

## 7. 验收与待确认事项

| 验收场景 | 预期 |
|---|---|
| 四路正常 | PB13 闭合后观察输入，四路吸合，2T 检查一次，PB13 先断，匹配确认后四路断开 |
| 输入波动、任一路压差超限、ADC 无效 | 故障原因和位图正确，尝试撤销全部输出 |
| 停止与启动或确认相邻到达 | 停止优先，旧的完成应答不能推进已停止的事务 |
| 接管应答缺失、旧序号或超时 | 不视为接管成功，验证超时撤销及故障上报 |
| MP10 单路缺失、掉线、自检失败或发送超时 | 该路样本不可用于判定，其他路继续工作 |
| PB13 闭合期间电流异常 | 继续收帧，暂停判定。释放稳定后使用新样本开始计时 |
| 频繁心跳、上报重发和 CAN 同时发生 | 核对半双工窗口、应答关联及控制时延 |
| 输出释放失败、复位和看门狗 | 尝试释放所有输出，故障可诊断。实板核对 GPIO、接触器及复位波形 |

进入实现与整机验收前，优先冻结四类条件：

1. **硬件与采样**：PB13 稳定时间，10% 波动基准，ADC 校准与有效范围，2T 检查偏差和异常撤销时限。
2. **漏电策略**：电流阈值、持续时间、重报和恢复规则，MP10 不可用时的启动与运行策略。
3. **接管与通信**：正式接管上限、超时后的整机处置、心跳周期与失联动作、RS485 主动上报窗口及重试次数。
4. **故障复位及调试**：故障如何解除，输出物理状态如何核验，Shell 直控何时允许使用。
